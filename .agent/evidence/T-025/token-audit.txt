# T-025 — D13 — Ombre modale gris chaud

## Constat initial (même pattern de contradiction que T-024/D12)

Analyse de la cascade réelle sur `#k-modal.k-modal` (`box-shadow`,
`@media (min-width: 900px)`) :

- `modal-shell.css:441` `box-shadow: 0 28px 80px var(--overlay-dark-sm)` — écrasé
- `modal-shell.css:769` `box-shadow: none` — **gagnant réel** avant correction
- `modal-shell.css:899` `.k-modal { box-shadow: 0 30px 80px var(--border-ocean-18) }`
  — mort par spécificité (classe seule < id+classe), jamais appliqué

L'ombre "ocean" visée par l'énoncé de la tâche n'était donc **pas rendue**
sur desktop avant correction (rendu réel = aucune ombre). Même cause que
D12 : commentaire/doc figé (`PALETTE-FIX-01`) décrivant une règle déjà
morte par spécificité au moment où elle a été écrite.

## Token créé

`tokens.css`, à côté de `--shadow-sm/md/lg` (même base `--text`,
convention "basées sur --text pour cohérence") :

```css
--shadow-modal-neutral-10: 0 24px 60px rgba(31,48,36,.10);
```

Reprend exactement la base RGB déjà utilisée par `--shadow-sm/md/lg` et
`--elev-1..4` (dérivée de `--text: #1F3024`, conforme à la note du plan
d'origine "neutre dérivé de --text-primary"). `tokens.css` n'est pas dans
le périmètre CSS de la feature `modal-product` → pas de littéral introduit
dans le scope compté par le gate `doctrine`.

## Corrections appliquées (modal-shell.css)

- Ligne ~769 (règle gagnante) : `box-shadow: none` →
  `box-shadow: var(--shadow-modal-neutral-10)`.
- Ligne ~899 (règle morte `.k-modal`) : teinte ocean retirée,
  remplacée par le même token, pour cohérence si la spécificité venait
  à changer un jour.
- Aucun `rgba()`/`#hex` littéral introduit dans `modal-shell.css`.
- Toute référence à `var(--border-ocean-18)` supprimée du fichier.
