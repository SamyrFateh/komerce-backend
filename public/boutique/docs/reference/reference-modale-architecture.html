Modale produit — un seul modèle, toute densité

Le même template rendu à deux extrêmes : un produit à 3 variantes et un à ~20. Aucune branche de code entre les deux, aucune hauteur calculée. Ce qui « affleure » sous le fold change tout seul selon ce qui remplit l'écran — c'est ça qui empêche d'avoir à « casser pour passer sur Temu ».

1

Un seul conteneur qui scrolle

Hero en hauteur relative, le reste flue, le conteneur défile. Zéro height en dur, zéro « rétrécir pour reloger ».

2

CTA sticky indépendant

Collé en bas, toujours atteignable — que la fiche fasse 600px ou 3000px. Il ne dépend jamais du contenu au-dessus.

3

Les variantes gèrent leur débordement

Swatches en flex-wrap : peu → 1 ligne, beaucoup → plusieurs lignes qui participent au scroll. Jamais de cadre à hauteur fixe qui tronque.

Même code, deux densités

À gauche, peu de variantes : couleur + taille tiennent en haut, et ce sont les suggestions qui affleurent (teasing cross-sell). À droite, beaucoup de variantes : le bloc couleur déborde et affleure (on scrolle dans les couleurs, façon SHEIN) ; les suggestions viennent plus bas, naturellement.

Ce qui affleure : le bloc couleur. 22 coloris ne tiennent pas au-dessus du fold — donc ils ne l'essaient pas : la grille déborde et affleure, on scrolle dans les couleurs. Même conteneur, aucune ligne de code en plus.

Pourquoi ça ne casse jamais : le layout ne connaît pas le nombre de variantes. Il empile image → prix → livraison → couleur → taille → suggestions dans un conteneur qui scrolle, CTA sticky en bas. À 3 variantes, les suggestions affleurent ; à 22, c'est la grille couleur — le même code, la densité décide. Le petit luxe que tu t'offres vs SHEIN : l'ordre (couleur + taille juste sous le prix) pour que, quand il y a peu de variantes, le choix soit immédiat. Un produit dense pousse juste les tailles plus bas — rien ne se brise.
