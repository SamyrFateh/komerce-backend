Architecture canonique de la modale produit v3.0

Cette référence fixe la composition, les propriétaires du scroll et la séparation des rôles entre hero, configurateur, détails, side cart desktop et actions mobiles.

Principe fonctionnel

La même séquence mentale sur desktop et mobile.

DÉCOUVRIR ↓ COMPRENDRE ↓ CONFIGURER ↓ ACHETER ↓ APPROFONDIR

Structure sémantique

Un seul contrat et un seul état de sélection.

ProductModal ├── ModalHeader ├── ProductViewport │ ├── ProductScroll │ │ ├── ProductHero │ │ ├── ProductConfigurator │ │ ├── ProductDetails │ │ └── ProductRecommendations │ └── DesktopCartPanel └── MobilePrimaryActions

Desktop — coque cible

La zone produit et le side cart sont deux régions sœurs. Le configurateur couvre la galerie et le récit produit, jamais le panier.

┌─────────────────────────────────────────────────────────────┬──────────────────┐ │ MODAL HEADER │ │ ├──────────────────────────────┬──────────────────────────────┤ │ │ │ │ │ │ GALERIE / MÉDIAS │ RÉCIT PRODUIT │ SIDE CART │ │ │ nom · prix · résumé │ │ │ │ livraison · bénéfices │ articles │ │ │ réassurance · partage │ quantités │ ├──────────────────────────────┴──────────────────────────────┤ sous-total │ │ CONFIGURATEUR TRANSVERSAL │ commander │ │ taille · couleur · modèle · quantité · actions │ │ ├─────────────────────────────────────────────────────────────┤ │ │ DÉTAILS STRUCTURÉS │ │ ├─────────────────────────────────────────────────────────────┤ │ │ SUGGESTIONS │ │ └─────────────────────────────────────────────────────────────┴──────────────────┘

Desktop — contrat de scroll

Le produit enrichi est plus long, mais ne change pas de mécanique.

ProduitHero, configurateur, détails et suggestions partagent un seul scroll.
Side cartRégion indépendante avec son propre flux interne si nécessaire.
InterditImage sticky pendant que les détails passent sous elle.

Desktop — répartition des rôles

ZoneResponsabilité
HeroDonner envie et expliquer rapidement le produit.
ConfigurateurAfficher tous les axes de choix d'un coup d'œil.
Side cartConfirmer l'ajout, modifier les quantités et commander.
DétailsDocumenter sans surcharger la colonne du hero.

Mobile — coque cible

Le mobile utilise trois lignes structurelles. Les actions ne flottent pas au-dessus du contenu.

┌──────────────────────────────────────────┐ │ HEADER │ │ retour · pager · panier · fermeture │ ├──────────────────────────────────────────┤ │ CONTENU SCROLLABLE │ │ │ │ média │ │ identité · prix · livraison · résumé │ │ configurateur pleine largeur │ │ détails │ │ suggestions │ │ │ ├──────────────────────────────────────────┤ │ ACTIONS PRIMAIRES │ │ Ajouter · Acheter maintenant │ │ + safe-area │ └──────────────────────────────────────────┘

Configurateur — comportement commun

Axes explicitesCouleur, taille, modèle, finition ou format possèdent chacun un libellé.
RespirationLes contrôles restent compacts ; l'espace libre n'est pas rempli artificiellement.
Flux naturelflex-wrap ou grille auto ; aucune hauteur fixe tronquante.
État partagéDisponibilité, prix et média proviennent du même reducer de sélection.
Indisponible visibleUne option incompatible ou en rupture reste stable et expliquée.
Produit simpleLe panneau se compacte sans changer de shell ni créer de vide.

Interdits d'architecture

× quatre arbres DOM runtime × galerie sticky dans le contenu produit × scroll distinct selon simple/enrichi × variantes enfermées dans une hauteur fixe × déplacement de blocs par JavaScript selon viewport × CTA mobile superposée au scroll × compensation de hauteur Samsung par mesure JS × duplication du side cart dans le configurateur
Règle de contrôle : le hero explique, le configurateur fait choisir, le side cart ou la barre mobile fait acheter. La richesse ajoute du contenu ; elle ne change jamais la coque.
