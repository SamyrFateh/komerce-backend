Modale produit — références v2.1

Un seul composant Product Detail s'adapte à 4 états selon la richesse du produit et le type d'écran. Rendu pixel-fidèle au design system Komerce réel — remplace la maquette abstraite v2.1 précédente.

Principes clés

  • Un même HTML sémantique, sections optionnelles activées par les capacités du produit.
  • Deux compositions responsive : Desktop (≥ 900px) et Mobile (< 900px).
  • Le panier latéral n'existe que sur Desktop.
  • Les actions primaires sont toujours accessibles.
  • Les recommandations (« Vous aimerez aussi ») sont présentes sur Desktop et Mobile.
iNe pas dupliquer 4 HTML différents. Utiliser des attributs et des classes d'état : data-richness="simple|enriched" data-layout="mobile|desktop".

Règles d'adaptation

Richesse produit

  • Simple : pas de galerie, pas de variantes.
  • Enrichi : galerie, variantes, promo et autres sections activées.

Écran

  • Desktop : grille 3 colonnes (media | contenu | panier).
  • Mobile : lecture verticale, panier dans le header, actions en barre sticky.

Actions

  • Ajouter : ajoute au panier sans fermer la modale.
  • Acheter maintenant : va à la commande.

Recommandations

  • Affichées après le contenu produit sur Desktop et Mobile, jamais masquées si le catalogue a des résultats.

Données

  • Les sections vides ne doivent pas être affichées (ex. variantes sur produit simple).
  • Aucun chiffre de stock, prix ou livraison inventé par le renderer.
iCette référence remplace le wireframe abstrait précédent. Le développement doit comparer son rendu à cette structure et à ces couleurs — pas à un gabarit générique. Pendant desktop : REFERENCE_MODALE_DESKTOP_2026-07.md (ASCII validé, ≥900px) — les deux se corroborent, aucune ne supersède l'autre.

Décision actée — Partage mobile

Matrice §3 (doc canonique) : Partage = Oui / Oui (simple, enrichi)     → confirmé
Cette référence visuelle (états 3 et 4) : réassurance nowrap 1 ligne
                                            + partage sur la ligne du dessous
Code prod actuel : partage absent sur mobile (Ct() gardé par d()=desktop) → reste à corriger

Layout tranché : même schéma qu'en desktop — réassurance compactée sur une seule ligne (flex-wrap:nowrap, déjà en prod côté mobile via le fix LOT1 de modal-shell.css), partage en ligne séparée juste en dessous (border-top). Le CSS mobile de .k-modal-share-row le supporte déjà. Seul le JS manque : Ct() (b-modal-desktop-enhancers.js) est gardé par d() (desktop uniquement) — il faut soit la rendre inconditionnelle, soit dupliquer l'injection dans b-modal-mobile-product.js.

Décision actée — Recherche interne retirée

Constat : la barre de recherche interne (.k-modal-inner-search) était injectée
         entre la description et #k-modal-suggestions, hors doc canonique §5.
         Sur mobile, elle entrait en conflit d'espace avec réassurance + partage
         (3 blocs à caser sur un écran déjà serré).
Historique : une loupe topbar (Sprint 4) avait déjà été retirée avant elle
         (REF-2026-07c) — deux zones de recherche, confusion + bug de reset
         d'état non réinitialisé à la fermeture de la modale.
Décision (REF-2026-07d) : retrait complet, flux vertical ET topbar — pas de
         nouveau point d'entrée recherche dans la modale.

Le flux mobile canonique redevient donc exactement §5 du doc de référence, sans écart à documenter : réassurance → partage → suggestions. Code retiré : barre inline, dropdown résultats, recherches récentes, recherche vocale (b-modal-core.js), CSS associé (modal-product.css, modal-shell.css, modal-product-lot4-hybrid.css). Le catalogue reste cherchable via la barre principale hors modale, inchangée.

Décision actée — Topbar mobile (REF-2026-07e)

Constat : la topbar mobile était en position:absolute par-dessus le média
         (full-bleed, §6.1 historique), avec un voile overlay-black + blur,
         et un bouton panier enfermé dans un disque blanc bordé.
Décision (REF-2026-07e) : la topbar redevient un enfant flex normal du
         shell, avant le média — espace réservé structurellement, pas de
         padding de compensation. Fond ivoire au repos (pas de bandeau
         sombre/gris/flouté), pager fusionné en une capsule unique, panier
         tressé affiché sans pastille de fond. Surface translucide légère
         autorisée uniquement à l'état scrollé.

Sur mobile, la topbar occupe une zone de respiration distincte du média. Ses contrôles sont légers et ne forment pas de bandeau sombre. Le pager est une capsule unique. Le panier tressé est affiché sans pastille de fond. Identique en mobile simple et mobile enrichi — la richesse produit ne change jamais le header. Code : css/modal-shell.css (owner unique, bloc mobile @media (max-width: 899px)), oracle tests/unit/modal-topbar-mobile.test.js.

Règle de gouvernance : un nouvel état visuel ne crée jamais un nouveau contrat Product Detail sans justification fonctionnelle explicite. Ce fichier est l'unique référence visuelle v2.1 — toute autre maquette antérieure est superseded.
