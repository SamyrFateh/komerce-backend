# KOMERCE VISUAL CANON V1

## Statut

**Canonique pour le Back Office Komerce à compter du 9 octobre 2026.**

Ce document fixe le langage de marque et de présentation. Il ne porte aucune vérité métier, aucun statut métier et aucune autorité fonctionnelle.

## Langage de marque

Komerce n'utilise plus le rose, le violet ou le bleu pastel comme couleurs de marque du Back Office.

La palette canonique est :

| Rôle | Couleur | Hex |
|---|---|---|
| Structure / autorité | Navy Komerce | `#071A3D` |
| Structure secondaire | Navy 2 | `#0D2A52` |
| Signature | Or Komerce | `#C9A227` |
| Signature forte | Or profond | `#A67C12` |
| Matière claire | Champagne | `#E7D7A3` |
| Surface chaude | Ivoire | `#FFF9F0` |
| Surface secondaire | Sable | `#F3EBDD` |
| Canvas | Blanc chaud | `#F8F6F1` |
| Texte | Ink | `#15213A` |
| Texte secondaire | Ardoise | `#65718A` |

Les couleurs rouge, ambre, vert et ardoise d'état sont réservées à une **sémantique métier réelle** :

- rouge = blocage / action requise ;
- ambre = risque / attention ;
- vert = normal / conforme ;
- ardoise = non observé / neutre.

Une couleur d'état ne sert jamais à décorer un Hero ou à donner une identité de rubrique.

## Une seule grammaire

Toutes les surfaces Canonical parlent le même langage :

- sidebar Navy ;
- marque et repères éditoriaux Or/Champagne ;
- Heroes Ivoire/Champagne ;
- cartes blanches ou ivoire très léger ;
- titres Navy ;
- textes secondaires Ardoise ;
- boutons primaires Navy ;
- contrôles blancs bordés ;
- ombres très légères ;
- rayons cohérents ;
- couleurs métier uniquement là où elles signifient quelque chose.

Les rubriques sont différenciées par leur **illustration métier, géométrie et contenu**, jamais par une palette indépendante.

## Hero canonique

Le Hero est le premier objet éditorial de la page, immédiatement après le contexte global de la surface.

Il porte :

1. un kicker métier court ;
2. un titre métier ;
3. une phrase de pilotage ;
4. les contrôles essentiels au contexte lorsqu'ils existent ;
5. une signature visuelle métier à droite.

Il ne porte ni jargon d'architecture, ni description longue, ni décoration sans sens.

Le Hero doit rester compact afin que la décision et l'objet principal restent visibles dans le premier viewport desktop.

## Signatures par domaine

| Domaine | Signature visuelle |
|---|---|
| Pilotage | réseau global, circulation, carte / routes |
| Action Center | décision, file prioritaire, marqueur d'exception |
| Commerce | activité, panier, progression commerciale |
| Commandes | séquence de cycle de vie |
| Operations | chaîne logistique, transport, hub, relais |
| Finance | position, rapprochement, valeur |
| Marchés | réseau de territoires et responsabilités |
| Sourcing | découverte, sélection, qualification |
| Achats fournisseurs | engagement, PO, confirmation |
| Expéditions & Douane | route internationale, frontière, libération |
| Comptabilité | rapprochement, lignes, clôture |
| Hub / Relais | flux physique local |
| Catalogue | sélection / validation / exposition |
| Atelier économique | prix, équilibre, structure économique |

Les illustrations utilisent Navy + Or + Champagne + Ivoire. Le bleu, le violet ou le rose ne deviennent jamais une identité de domaine.

## Hiérarchie

La hiérarchie existante reste obligatoire :

**Hero → Attention → Primary → Secondary**

Le Hero donne l'identité. Attention porte ce qui exige une décision. Primary porte l'objet métier principal. Secondary reste discret.

## Règle de contrôle

Avant d'ajouter une couleur ou un composant, poser deux questions :

1. **Est-ce Komerce ou est-ce une nouvelle mini-marque locale ?**
2. **Cette couleur signifie-t-elle quelque chose de métier ?**

Si la réponse à la première est « mini-marque » ou à la seconde « non », la proposition n'est pas canonique.
